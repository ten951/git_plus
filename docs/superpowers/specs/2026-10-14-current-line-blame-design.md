# Git Plus 光标行 Git Blame 设计

## 目标与效果

为 IntelliJ IDEA 提供光标所在行的 Git Blame 行尾提示。用户提供的截图是首版视觉依据：

```text
return result;  yangxingnong · 2天前 · fix: 修复查询逻辑
```

提示是编辑器虚拟文字，不写入文档、不参与复制和 Git diff。使用随编辑器主题变化的浅灰色，和源码之间保留间距。仅展示当前编辑器主光标所在行，换行后移除旧提示。

## 首版范围

- 自动显示作者名、相对提交时间、提交说明第一行。
- 提交距当前时间不超过 3 天（72 小时，含边界）时使用相对时间（“刚刚 / N分钟前 / N小时前 / N天前”）；超过 72 小时后显示完整提交时间，格式为 `yyyy-MM-dd HH:mm:ss`，例如 `2026-10-14 11:30:05`，按 IDE 所在系统的本地时区展示。
- 相对时间不足一分钟显示“刚刚”，其余向下取整。以展示时的当前时间计算，未来提交时间显示完整提交时间。
- 光标行包含本地未提交改动时显示“尚未提交”，不沿用旧行的提交信息。已暂存但尚未提交的改动同样处理。
- 已提交文件中的未修改行继续显示对应提交的信息，即使文件其他行存在修改或插入。
- 非 Git 文件、未跟踪文件、无提交仓库、二进制文件以及查询失败时不显示提示；失败仅记录诊断日志。
- 不增加工具窗口、悬浮详情、点击跳转或设置界面。软换行时显示在该逻辑行最后一个视觉行的末尾。

## 实现结构

保留仓库现有 Kotlin 和 IntelliJ Platform Gradle 工程。使用项目级控制器协调三个职责：

1. 编辑器事件：监听主光标换行、文档修改、文件切换和编辑器关闭；同一逻辑行内移动不重复查询。
2. Blame 查询：在后台取得 Git 逐行归属，并将当前文档行映射到相应 Git 行；优先评估平台自带 Git 支持，具体 API 在实现前根据目标 SDK 核实。
3. 行尾渲染：在 UI 线程创建或替换编辑器行尾 inlay，管理其生命周期。

首选平台 Git 支持，便于复用仓库识别和归属信息；备选为后台调用本地 Git 并解析结构化 blame 输出，但会增加命令执行和文档映射工作。不使用改写源码注释的方式。

## 刷新与正确性

- 快速移动光标采用约 150ms 的防抖，避免每次光标事件触发 Git 查询。
- 缓存以仓库、文件、Git 版本及文档版本为依据；文档修改、HEAD 或索引变化时失效，避免展示过期归属。
- 查询捕获编辑器、文件、主光标行和文档版本。结果返回时重新校验，过期结果丢弃。
- 文档变化后立即清除旧提示，待查询完成重新显示。只在明确判定行未修改时展示提交信息。
- 编辑器关闭或项目释放时清理监听器、任务和 inlay。
- Git 查询不阻塞 UI 线程。

## 验证与交付

自动验证关注行为边界：提交信息格式、未提交状态、插入行后的映射和过期查询结果。构建应验证目标 SDK 编译及插件打包。

在沙盒 IDEA 中人工检查：打开 Git 文件、主光标换行、快速移动、编辑和撤销、暂存改动、切换文件、多编辑器、软换行、浅色和深色主题，以及项目关闭。效果应与用户截图一致，且源码保持不变。

最终交付本地代码、插件安装包（构建环境允许时）和安装/使用说明。当前阶段不 commit、push 或发布。

## 当前依据与待核实项

仓库当前只有模板示例，构建配置指定 IntelliJ IDEA 2025.3.6.1。设计基于用户已确认的光标行范围及截图样式。

实施选择：采用设计中的备选方案，使用 Git `blame --line-porcelain --contents -` 查询当前文档快照，直接由 Git 映射未保存及已暂存改动；不依赖平台内部行映射 API。行尾采用平台 after-line-end inlay API，已在目标 SDK 编译验证。

资源边界：首版跳过超过 100 万字符的文档及超过 32 MB 的查询输出；单条 Git 命令最多运行 15 秒。缓存最多保留四个快照。上述限制用于防止大文件或慢仓库长期占用后台资源。
